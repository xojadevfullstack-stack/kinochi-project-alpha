## 2. Nima Uchun Eski Migratsiyalarga Tegildi? (RAW Error Reproduce)

Asl holatda (`d5fbaae~1`), `c011ec7100`, `d012ec7201` va `e013ec7302` fayllari bitta `op.execute(""" ... ; ... ; """)` ichida bir nechta SQL statement yuborgan:
- `c011ec7100`: `CREATE TABLE ...; CREATE INDEX ...; CREATE INDEX ...;`
- `d012ec7201`: `ALTER TABLE broadcasts DROP COLUMN ...; ALTER TABLE ...;`
- `e013ec7302`: `CREATE TABLE ...; CREATE INDEX ...; CREATE INDEX ...;`

PostgreSQL serverining `prepare` protokoli (va uni ishlatuvchi `asyncpg` drayveri) bitta `PREPARE` ifodasiga bittadan ortiq SQL buyrug'i berilishiga ruxsat bermaydi. Shuning uchun `asyncpg` orqali Alembic ishga tushganda quyidagi RAW xatolik yuzaga keladi:

## 3. SQL Ekvivalentligi Tahlili

Har bir faylda bajariladigan SQL to'liq solishtirildi:

1. **`c011ec7100_add_collection_subscriptions.py`**:
   - Asl SQL: 
     - Statement 1: `CREATE TABLE IF NOT EXISTS collection_subscriptions (...)`
     - Statement 2: `CREATE INDEX IF NOT EXISTS ix_collection_subscriptions_user_id ON collection_subscriptions(telegram_user_id);`
     - Statement 3: `CREATE INDEX IF NOT EXISTS ix_collection_subscriptions_collection_id ON collection_subscriptions(collection_id);`
   - O'zgartirilgan SQL: Aynan shu 3 ta statement alohida 3 ta `op.execute` ga bo'lingan.
   - **Xulosa:** Harfma-harf bir xil. Yangi ustun, yangi constraint, yoki mantiqiy o'zgarish mutlaqo **YO'Q**.

2. **`d012ec7201_add_broadcast_media_and_buttons.py`**:
   - Asl SQL (downgrade):
     - `ALTER TABLE broadcasts DROP COLUMN IF EXISTS button_url;`
     - `ALTER TABLE broadcasts DROP COLUMN IF EXISTS button_text;`
     - `ALTER TABLE broadcasts DROP COLUMN IF EXISTS media_url;`
     - `ALTER TABLE broadcasts DROP COLUMN IF EXISTS media_type;`
   - O'zgartirilgan SQL: Aynan shu 4 ta statement alohida 4 ta `op.execute` ga bo'lingan.
   - **Xulosa:** Harfma-harf bir xil. Yangi ustun yoki mantiqiy o'zgarish **YO'Q**.

3. **`e013ec7302_create_content_requests_table.py`**:
   - Asl SQL:
     - `CREATE TABLE IF NOT EXISTS content_requests (...)`
     - 6 ta `CREATE INDEX IF NOT EXISTS ...`
   - O'zgartirilgan SQL: Aynan shu 1 ta table yaratish va 6 ta index yaratish alohida `op.execute` ga bo'lingan.
   - **Xulosa:** Harfma-harf bir xil. Hech qanday mantiqiy o'zgarish **YO'Q**.

## 6. Render/Vercel Deploy'da `alembic upgrade` Avtomatik Ishlaydimi?

**Javob:** **YO'Q, avtomatik ishlamaydi.**

Tadqiqot natijalari (kod bazasi bo'yicha):
1. **Dockerfile:** 
   - Root `Dockerfile` dagi startup buyrug'i: `CMD ["python", "run.py"]`.
   - `backend/Dockerfile` dagi buyruq: `CMD sh -c "uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}"`.
2. **`run.py`:**
   - Faqat `run_api()` (uvicorn) va `supervised_run_bot()` (aiogram) ni ishga tushiradi. Ichida Alembic buyruqlari yo'q.
3. **`backend/app/main.py` lifespan:**
   - FastAPI lifespan faqat `Base.metadata.create_all` qiladi (mavjud bo'lmagan yangi jadvallarni yaratadi, mavjud jadvallarga yoki Alembic versiyasiga tegmaydi).
4. **Production migratsiya nazorati:**
   - Production migratsiyalari faqat va faqat `ops/go_live.ps1` dagi `MIGRATE` bosqichi orqali amalga oshiriladi (u yerda `alembic heads` tekshirilib, faqat 1 ta head bo'lgandagina `alembic upgrade head` qilinadi).
   - Shuning uchun merge commit'ning `main` ga qo'shilishi yoki deploy bo'lishi production bazasida o'zboshimchalik bilan migratsiyani bajarmaydi.
